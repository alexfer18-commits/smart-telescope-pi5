# smart-telescope-pi5

A low-cost, autonomous pointing instrument: a Raspberry Pi 5 solves the sky
locally and closes the loop on two NEMA 17 steppers. The repository contains the
mechanical design, the control software, the inference benchmark, and the
protocol for the comparative study of CPU, accelerator, and cloud inference.

The scientific claim this code exists to test: **an accelerator buys latency,
not accuracy, in a pointing instrument — and at amateur utilisation the cloud is
cheaper per inference.** Both halves of that sentence are measured, not assumed.

**E2 needs hardware that is not the telescope.** The Hailo-8L executes a `.hef`
compiled by the Dataflow Compiler, which only runs on x86_64 Linux. The Pi is an
inference target, never a compiler target: the experiment requires a VM, a remote
server, or a dedicated x86 machine. See `docs/architecture.md`, "Hailo-8L
Compilation Constraint".

## Mechanical design

[`docs/mechanical_analysis.md`](docs/mechanical_analysis.md) works the numbers
before anything is printed:

- **Torque.** An unbalanced 2.5 kg tube on a 20 cm lever needs 4.91 N·m; the
  NEMA 17 gives 0.28 N·m at the 1.2 A the A4988 can take. Direct drive is short
  by 17× (0.06× of the required torque). Balanced, the same drive needs
  0.045 N·m and has a **6.2× margin**, tolerating ±8 mm of centroid offset — so
  the build balances the tube instead of buying a gearbox.

> The mount MUST be balanced (counterweight ~150g) to stay within the NEMA 17
> torque envelope. Unbalanced, the motor cannot move the tube.

[`figures/torque_comparison.pdf`](figures/torque_comparison.pdf) plots the three
numbers against the motor limit; it is generated by
`figures/torque_comparison.py`.
- **Resolution.** 1.8°/16 = 6.75 arcmin/step against a 10 arcmin target: fits,
  but spends 68 % of the budget. The real limiter is the ±5 % step-angle error
  (±5.4 arcmin), which microstepping does not fix and a 5:1 belt does.
- **Structure.** 2020 extrusion deflects 0.12 mm over 200 mm (3.1 arcmin);
  printed PETG over the same span deflects 2.45 mm (63 arcmin). Long cantilevers
  are aluminium, short ones can be printed.

`hardware/ASSEMBLY_GUIDE.md` is the build order (Vref before the motor is
connected, GND before VMOT, torque per fastener) and
`figures/assembly_exploded.png` / `figures/assembly_side_view.png` are drawn
from the same dimensions as the `.scad` files by `figures/assembly_diagrams.py`.
The `.scad` files are **syntax-checked but not rendered**: OpenSCAD is not
installed on this machine.

## Install

On the Pi (Raspberry Pi OS 64-bit, kernel 6.12):

```bash
sudo apt install -y python3-picamera2 libcamera-apps astrometry.net
git clone https://github.com/alexfer18-commits/smart-telescope-pi5
cd smart-telescope-pi5
python3 -m venv .venv && . .venv/bin/activate
pip install -r pi5-software/requirements.txt
pytest                                   # 26 tests; 6 need a running broker
TELESCOPE_API_TOKEN=change-me uvicorn dashboard:app --host 0.0.0.0 --port 8443
```

On a laptop, everything except GPIO works:

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r pi5-software/requirements.txt matplotlib
pytest
python benchmarks/compare_inference.py --episodes 300
```

Stack deployment (broker, dashboard, metrics):

```bash
./scripts/deploy.sh        # generates .env, CA, server cert, MQTT identities
```

## Benchmark

`benchmarks/compare_inference.py` runs the same quantized graph on TFLite CPU,
ONNX CPU, Hailo-8L, and a modelled AWS Lambda call. Latest run on this host —
**synthetic latency, not a measurement**, because no runtime was installed:

| Backend | p50 (ms) | p95 (ms) | Wh / 1000 inf | USD / 1000 inf | Source |
|---|---|---|---|---|---|
| cpu_tflite | 162.2 | 234.3 | 0.346 | 0.000 | synthetic |
| cpu_onnx | 149.4 | 201.5 | 0.315 | 0.000 | synthetic |
| hailo8l | 15.9 | 19.0 | 0.044 | 0.000018 | synthetic |
| cloud_lambda | 206.2 | 429.1 | 0.060 | 0.000200 | synthetic |

Two things follow, and only the second is obvious. The accelerator delivers
**10.2× the median throughput** — H1 holds. But the cost crossover sits at
**14.6 M inferences/month** against a $70 HAT amortised over 24 months, while an
amateur run is ~400 inferences/month: the accelerator never pays back on
marginal cost. H3 holds with a wide margin.

Rerun on the Pi with a real model to replace every "synthetic" above:

```bash
python benchmarks/run_real_measurements.py --model ml-model/mnv3_int8.onnx \
    --episodes 300 --ina219
```

That script writes `data/real_measurements.json` with `"source": "measured"` and
the model hash; it has no synthetic fallback, so a missing runtime produces a
skip, not a guess. The JSON from the synthetic harness carries
`hailo_available` plus `source` per backend and `energy_source` per row; the
figure prints a red warning when any row is synthetic. Never quote a synthetic
row as a measurement. Provenance rules: `experiments/experimental_protocol_v2.md`
for the benchmark, `experiments/experimental_protocol_v3.md` for the 3 × 3
pointing experiment (whose 270 rows are all synthetic:
`data/simulated_results_v3.csv` → `figures/anova_results_v3.pdf` and
`experiment_results_v3.xlsx`).

## Control and safety

- Altitude soft limits `[-5°, 95°]`, azimuth bounded to one rotation, enforced
  in `MotorController` — a shared MQTT credential is not an interlock.
- Commands are JSON, ≤ 512 bytes, axis-whitelisted, degree-bounded; retained
  messages are dropped so a command cannot replay on reconnect.
- MQTT is TLS-only on 8883 (and 9001 for the app) with two identities and
  per-topic ACLs: `pi` writes state and reads commands, `phone` reads state and
  writes commands, and neither can do the other's job. Anonymous clients are
  rejected by the broker and by the bridge.
- The dashboard refuses to start without `TELESCOPE_API_TOKEN`.
- Findings and residual risks: `docs/security_report.md`.
